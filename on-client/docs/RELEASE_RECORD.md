# 케셰브 릴리스 기록과 새 환경 재현 기록 (22단계)

작성: 정예린 (ALEPH 보안 과정 대전 C반)

> 이 문서의 「재현 기록」은 **학생 진술**입니다. ALEPH 서버가 새 환경에서 실행했다는 뜻이 아니며, AI 원문 검토 결과는 실행 성공의 증명이 아닙니다.
> 이 버전은 **검증 중 버전**입니다. 실제 SDP 연결·실제 AI 설명·실제 조치 집행(19단계)·실제 OSV 조회가 확인되지 않았습니다. 22단계 통과는 원문 검토 기준의 수료이며, 실제 운영 인증이나 v1.0 자동 인증이 아닙니다.

### 3-1. 절차 (실제로 입력한 순서)

```bash
cd "$HOME/Desktop"
git clone https://github.com/yerinnnnn317/choi-bujang-secret-vault.git keshev-repro-22
cd keshev-repro-22
git checkout 8b399fc52400340097f1e03287bf25a6a1423e5a
cd on-client
powershell -NoProfile -ExecutionPolicy Bypass -File ./tools/start-alekov.ps1 -NoNativeHost
```

npm 설치 단계는 없습니다. `on-client`는 외부 npm 의존성과 `package-lock.json`이 없습니다(원문 확인).

## 4. 같은 최종 커밋 기준 정리

- 재현은 `8b399fc` 에서 했습니다.
- 22단계 제출 커밋은 `8b399fc` 다음에 **이 문서(`on-client/docs/RELEASE_RECORD.md`) 추가, `on-client/docs/STUDENT_RUNBOOK.md`의 장애 표 한 줄 추가(Git Bash 경로), `on-client/README.md` 학생 절의 확인 범위 문구와 링크, `STUDENT_RUNBOOK.md` 확인 표의 재현 줄**만 바꿨습니다. 코드·설정·실행 파일·잠금 파일은 바뀌지 않았습니다. 학생은 `git diff --stat 8b399fc HEAD`로 이를 대조할 수 있습니다.
- 그래도 제출 커밋 자체를 새 폴더에서 다시 실행한 기록은 없으므로, 제출 커밋의 새 환경 실행은 **미확인**으로 둡니다. 서로 다른 커밋의 결과를 합쳐 최종 버전 전체 성공으로 표시하지 않습니다.

## 6. 이동 가능한 구성

| 필요한 것 | 어디에 | 비고 |
|---|---|---|
| 실행 코드 | 저장소의 `on-client/` 전체 | clone 으로 받음 |
| 런타임 | Node.js 22~24 (기준 24.19.0) | `package.json`의 `engines`, 실행 도구가 검사 |
| 설정 예시 | `on-client/.env.example` | 비밀값 없음. 포트·어댑터·모델·OSV 허용 목록 변수 이름만 |
| 설치 절차 | `on-client/docs/STUDENT_RUNBOOK.md` 4장 | npm 설치 없음 |
| 경로 | 문서의 `바탕 화면\…`, `$HOME/Desktop/…`는 이 PC에서 쓴 예시 | 코드는 로컬 절대경로에 의존하지 않음. 실행 도구는 자기 위치(`$PSScriptRoot`) 기준 |
| 비밀값 | 저장소에 없음 | `.env`, `.env.*`는 `.gitignore`. 계정 연결·SDP 설정은 프로젝트 밖 |
